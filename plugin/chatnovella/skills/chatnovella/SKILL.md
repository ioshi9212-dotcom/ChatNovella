Прочитай [порядок работы](references/workflow.md) перед настройкой или
продолжением новеллы. Используй инструменты MCP-сервера ChatNovella.

Перед каждой сценой сначала вызови `prepare_novella_turn` с пустым списком участников, прочитай **все** чанки и разведочный индекс NPC. Рассмотри арки, прошлые события, прошедшее время и инициативу других персонажей. **До написания сцены** зафиксируй план через `plan_novella_scene`. Затем выбери фактических участников, получи новый `prepare_novella_turn` и все его чанки. Без предварительного плана сервер не одобрит сцену. Не заставляй персонажей появляться ради галочки.
Успешно сохрани сцену через `save_novella_turn` до её публикации.
При сохранении обязательно передай `packet_id` последнего подготовленного
игрового пакета; его **все** чанки должны быть прочитаны инструментом.
Без этого сервер отклонит сохранение.
**Каждый ход** обязательно передавай `timeline_events`: только краткие
значимые факты с датой, либо пустой список с `timeline_no_change_reason`.
Amvera сама дополняет хронологию. Не передавай `state/timeline.md` как
обычный изменённый файл. Для исправления старой памяти используй
`repair_novella_timeline`, не создавая лишний игровой ход.
Не подменяй фактический ответ инструмента выдуманным результатом.

Все восемь файлов `engine/` обязательны. После полного черновика выполни
восемь проверок `engine/scene_review.md` и вызови `review_novella_scene`.
Передай конкретные `checks` и `relationship_labels` участников. Исходный
черновик плюс **пять исправленных версий**; новый пакет не сбрасывает
лимит. Дополнительно обязательный `scorecard`: шесть оценок 0–2, конкретные
цитаты из готовой сцены, подтверждение ввода читателя, обязательный `pov_actions` с источником каждого нового значимого выбора POV (самого читателя или уже сохранённого действия), критические нарушения,
проверка замыливания/затемнения. Сервер сам считает не менее 11/12 и требует
отсутствия критических нарушений; при `approved=false` исправляй именно
дефекты. При `blocked=true` остановись и не публикуй брак.
При `approved=true` передай `review_id` в `save_novella_turn` с теми же текстом,
вводом читателя, файлами, хронологией и пакетом. Сервер отклоняет подмену.
Публикуй только успешно сохранённый текст без чек-листа и служебного отчёта.
Смысл проверяет GPT, сервер — структуру, числа, лимит и совпадение записи.

Числовые показатели NPC→POV обязательны: до старта 1–10 индивидуальных шкал
0–100 с дельтой 0 по канону; затем сохраняй шкалы и показывай значение/дельту
даже без изменения. NPC→NPC остаётся словами. Если в старой игре чисел нет,
после чтения карточек используй `initialize_novella_relationship_metrics`: он
проверяет историю, сохраняет текст и не добавляет игровой ход. Не называй
новые стартовые оценки восстановленными историческими значениями.

Отношения ведутся численно только у NPC с сохранённой карточкой. Охраннику
или прохожему без неё не придумывай шкалы. Переноси все явно заданные автором
чувства: семь чувств — семь шкал, без отбора трёх главных. В существующем
пункте проверки `npc` передавай `relationships` как JSON-строку с решением
`changed`/`unchanged` и конкретной `reason` для каждого карточного участника
и каждого изменённого за кадром relations.md. Оцени влияние событий на все
шкалы; без причины не меняй, при наличии причины не замораживай. Формат —
в `engine/scene_review.md`. Пропущенные шкалы явного авторского списка можно
дополнить через существующий `initialize_novella_relationship_metrics` без
хода и изменения имеющихся значений. Не выдавай новые оценки за старые числа.
