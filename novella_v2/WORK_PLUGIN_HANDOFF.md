# Задание для ChatGPT Work: ChatNovella V2 — основной движок

**Главное:** ChatNovella V2 теперь разворачивается из ветки `main`
репозитория `ioshi9212-dotcom/ChatNovella`, в **действующем**
проекте Amvera на его текущем домене. Отдельный проект Amvera НЕ нужен.

Сервер запускается корневым `amvera.yaml`:
`uvicorn novella_v2.amvera_entry:app --host 0.0.0.0 --port 8080 --workers 1`.
Зависимости — `novella_v2/requirements.txt`. Хранилище V2 —
`/data/chatnovella-v2`; старые LITE_ данные — в
`/data/chatnovella-lite`, не трогать и не удалять.
`chatnovella_lite/`, `chatnovella/` и старые папки плагинов
остаются в репозитории, но не участвуют в запуске.

### Что сделать

1. Убедиться, что **существующий** проект Amvera получает актуальный
   `main`, выполнить/дождаться сборки и перезапуска.
   Не создавать отдельный Amvera-проект. Если Amvera не следит
   за main автоматически, обновить её текущую привязку к main.
2. Проверить на **прежнем домене** `GET /healthz`:
   `engine: chatnovella-v2`, затем `GET /v2/instructions`
   и `GET /openapi.json` → 200, **без токенов**.
   `/mcp` — Streamable HTTP MCP, 13 типизированных инструментов
   V2. При ошибке 421 проверить `CHATNOVELLA_V2_PUBLIC_HOST`
   на точное имя действующего домена (без https, пути, порта).
3. Обновить **подключение ChatNovella**, чтобы инструменты работали
   через новый `/mcp`, а не через старые Lite endpoints.
   Создавать только `NV2_` сессии. Плагин не должен спрашивать
   API-key/Bearer: auth.type=none. Код сборки пакета:
   `novella_v2/build_plugin.py` из main.
4. При запуске нового чата прочитать `load_v2_instructions`
   **один раз** (Rules + авторский Skin Builder); обновлять
   по отдельной команде. Не заменять и не переписывать Skin Builder.
   На каждом игровом ходе подготовить пакет, прочитать все
   непрочитанные чанки, проверить SHA-256 и сохранить по тому же
   `request_id`. Возвращать повествование только после saved=true.
   В контексте каждого игрового хода есть отношения и открытые арки.
   Соблюдать личные знания, статусы знакомства и свидетельства
   изменений, аудиты 15/60, корректные откаты.
5. Провести **новую тестовую** сессию `NV2_`: canon, approve,
   opening, prepare/chunks, turn, status/history и duplicate replay.
   Проверить сохранение после перезапуска. Не записывать тестовые
   ходы в старые реальные `LITE_` сессии.

### Очень важное о старом чате

V2 **не умеет читать LITE_**. Старый чат остаётся сохранённым
в старых данных, но после переключения сервера не сможет
продолжаться через старые Lite-инструменты.
Ничего из `/data/chatnovella-lite` не удалять.
Для восстановления старого режима можно временно вернуть
предыдущую конфигурацию запуска Lite из истории GitHub,
не трогая данные. Автоматическую миграцию не обещать.

### Отчёт

Сообщить действительный URL, номер ревизии на сервере,
результаты health/MCP вызовов, подключённый ChatGPT плагин,
результаты тестовой NV2-сессии и состояние хранилища.
**Не заявлять «Amvera подключена», пока нет проверки живого сервера.**

**Риск открытого сервера:** пользователь отказался от токена.
Это значит, что REST и MCP доступны без авторизации, и любой
обладатель ID сессии может её прочитать и изменить.
Для конфиденциальности нужна защита на уровне хостинга/сети.
