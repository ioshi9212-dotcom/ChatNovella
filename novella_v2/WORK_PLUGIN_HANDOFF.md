# Задание для ChatGPT Work: новый плагин ChatNovella V2

## Принципиальная граница

НЕ редактировать/перенастраивать подключённый плагин `ChatNovella Lite`,
его `LITE_` сессии, старые инструменты и старый домен. Создать
**самостоятельное** подключение `ChatNovella V2` (или добавить рядом
новые инструменты, если раздельное подключение технически невозможно,
но ничего не удалять).

Новый V2 находится в Github `ioshi9212-dotcom/ChatNovella`,
сборка в отдельной ветке
`deploy/chatnovella-v2-amvera-20261124`.
Руководство по Amvera — `novella_v2/AMVERA_DEPLOY_GUIDE.md`.
Исходный контракт — `novella_v2/api.py`, `novella_v2/rules.md`,
`novella_v2/README.md`, `novella_v2/engine.py`.
Не менять/не переписывать `novella_v2/skin_builder.md` (стиль — автора).

## Хостинг и авторизация

V2 — отдельный FastAPI REST-сервис с собственным Amvera URL,
который появится после создания **второго** Amvera-проекта, и
собственным секретом `CHATNOVELLA_V2_TOKEN` (Bearer).
Токен не помещать в код или тексты переписки.
Данные новой службы: постоянный `/data/chatnovella-v2`
внутри её собственного проекта. Сессии начинаются `NV2_`.
Lite-сессии начинаются `LITE_` и остаются в старом сервере.
Архивные `CN_` не мигрируются автоматически.

## Действия Work

1. Получить отдельный URL и авторизованный доступ к V2 (если Amvera
   ещё не создана — сначала создать второй сервис по руководству).
   Проверить `GET /healthz` → engine=chatnovella-v2,
   `GET /v2/instructions` без Bearer → 401,
   с Bearer → 200 и контрольные суммы.
2. Построить **отдельный типизированный MCP-адаптер** либо новую
   конфигурацию Actions, использующую REST V2. Текущие V2-эндпоинты
   используют тела dict, поэтому для коннектора потребуется явная
   схема параметров/адаптер: не пытаться использовать прежние
   Lite `create_lite_session`/`save_lite_turn` на новом URL.
   Реализация адаптера подготовлена в `novella_v2/mcp_adapter.py`
   и подключена к V2 API по `/mcp`; типы — `mcp_models.py`,
   инструкции MCP — `MCP_INSTRUCTIONS.md`. На Amvera требуется
   `CHATNOVELLA_V2_PUBLIC_HOST` с фактическим новым доменом.
   Пакет отдельного плагина собирает `build_plugin.py` **после**
   проверки этого URL. Токена в пакете нет.
3. Обеспечить инструменты создания сессии, проверки статуса,
   утверждения канона, opening, добавления персонажа,
   подготовки пакета `prepare`, чтения `chunks`, `commit`,
   `audit`, поиска истории, `rollback` и инструкции/версии
   (см. все маршруты в `novella_v2/api.py`).
4. По запросу «Начнём» отправлять авторский текст дословно,
   полное распределение исходных фрагментов и names,
   начальные relationships с направленным familiarity и при
   необходимости initial_threads. До подтверждения canon_hash
   нельзя создавать сцену.
5. **Только один раз на новый чат** вызывать
   `GET /v2/instructions`, получать Rules + Skin Builder целиком.
   По отдельной команде «обнови Rules и Skin Builder» — повторять
   запрос. Не скачивать оба файла в каждом игровом ходе.
6. Каждый новый ход: стабильный request_id; prepare с reader_text
   и реальными участниками; дочитать только неполученные чанки
   и сверять chunk_hashes; генерировать сцену по канону и уже
   полученному Skin Builder; commit только с исходными
   request_id/packet_id/chunk_hashes и сохранённым вводом.
   При already_committed_duplicate вернуть исходную narration.
   Показывать художественный текст только при saved=true.
7. Состояние с полными восьмью полями в `state`. `knowledge`
   только реально наблюдавшему POV/NPC с точной цитатой из
   narration. `scene_access` нужен, если персонаж участвовал,
   но не остался в конечном present/remote: он должен иметь
   буквальное свидетельство участия в текущей сцене.
   Знания персонажей не распространять автоматически.
8. `relationships.md` включён в каждый пакет. Направленное
   знакомство: unaware (нет записи), aware, acquainted.
   NPC→POV — авторские шкалы 0–100, обычная дельта до ±3;
   сильный скачок — significant=true, reason и точное evidence.
   NPC→NPC — краткие словесные связи. Если изменений нет,
   relations=[]. Не менять стиль/формулировки автора.
9. `open_threads.md` входит **каждый ход**, хотя Rules/Skin
   Builder загружаются один раз. Поле `thread_updates` — только
   реальное изменение с цитатой source; статус closed убирает
   рабочую строку, оставляя исход в архиве. Нельзя заставлять POV
   завершать сюжетные линии по таймеру.
10. Аудит на 15/60 обязателен. При исправлениях knowledge/timeline
    и отношений требовать источники/evidence; правила отношений
    неизменны без разрешённой авторской операции.
11. Проверить отдельную тестовую `NV2_` сессию end-to-end,
    сохранность после перезапуска V2, отсутствие утечек в знаниях.
    Отдельно убедиться, что прежнее подключение Lite продолжает
    читать старые `LITE_` сессии. Не писать тестовые сцены в
    реальные старые сессии.

## Окончательный отчёт Work

Сообщить: реальный URL V2, какой отдельный проект Amvera создан,
название/ID нового плагина, какие V2-инструменты доступны, какие
проверки прошли, сохранность после перезапуска, подтверждение
работоспособности старого Lite. Не писать «подключено», пока
сервер действительно не запущен и плагин не вызывает V2.
