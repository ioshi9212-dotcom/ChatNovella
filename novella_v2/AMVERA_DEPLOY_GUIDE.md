# ChatNovella V2 — безопасный запуск на Amvera отдельным сервисом

**Статус:** подготовлена конфигурация в ветке GitHub; это НЕ означает,
что сервис уже создан, запущен или имеет публичный адрес.

## Почему отдельный сервис

- Живой Lite продолжает запускаться из `main` через корневой `amvera.yaml`.
  Эта ветка `deploy/chatnovella-v2-amvera-20261124` — специальная
  **только для второго проекта** Amvera, в ней корневой `amvera.yaml`
  указывает на `novella_v2.amvera_entry:app`.
- Не переключать старый Amvera-проект с `main` на эту ветку и не
  переназначать ему старый домен: это вырубит Lite-инструменты.
- Данные каждого Amvera-проекта хранятся отдельно. У V2 абсолютная
  директория `/data/chatnovella-v2` (в собственном Data-подключении
  **второго проекта**); у Lite остаётся его старое `/data`.
- Никакой автоматической миграции сессий `LITE_` и `CN_` в `NV2_`.
  При работе в V2 создавать новые сессии, старые продолжать только через Lite.

## Однократные действия в Amvera

1. Открыть [Amvera Cloud](https://cloud.amvera.ru/projects) и **создать
   НОВОЕ приложение** (например, ChatNovella V2). Не выбирать существующий
   сервис ChatNovella Lite. Учитывать, что отдельный проект может
   тарифицироваться дополнительно.
2. Во вкладке «Репозиторий» подключить GitHub
   `ioshi9212-dotcom/ChatNovella`, выбрать **ТОЧНУЮ ветку**
   `deploy/chatnovella-v2-amvera-20261124`. Не main. Проверить,
   что корневой файл `amvera.yaml` там запускает
   `novella_v2.amvera_entry:app`, а не `chatnovella_lite.server:app`.
3. В «Переменные» создать **секрет**, НЕ обычную открытую переменную:
   `CHATNOVELLA_V2_TOKEN` — уникальное случайное значение длиной
   минимум 24 символа, практически лучше 32–64. **Не записывать
   токен в GitHub, чат, документы, логи или скриншоты**.
   `CHATNOVELLA_V2_DATA_DIR` задавать необязательно: entrypoint сам
   использует `/data/chatnovella-v2`. При ручной установке допускать
   только собственную папку под постоянным `/data`.
4. Проверить Amvera-конфигурацию: Python 3.12;
   `build.requirementsPath: novella_v2/requirements.txt`;
   Uvicorn на `0.0.0.0:8080`, **один** worker;
   `run.persistenceMount: /data`.
   Не указывать в новом проекте корневой Lite `requirements.txt`.
5. Запустить сборку и деплой **в новом проекте**, включить
   **отдельный публичный адрес** для V2. Адрес нельзя угадывать,
   он появится в карточке нового проекта. Существующий Lite URL
   не менять.
6. Проверить, что `GET https://<новый-домен>/healthz` возвращает
   `{"status":"ok","engine":"chatnovella-v2"}`.
   Затем проверить:
   - `GET /v2/instructions` без токена → HTTP 401.
   - `GET /v2/instructions` с `Authorization: Bearer <секрет>`
     → HTTP 200, `rules` и `skin_builder` с контрольными суммами.
   - `GET /openapi.json` без токена → HTTP 401.
   - Убедиться, что новый Skin Builder прочитан из **актуальной
     ветки**, а не старого Lite.
7. Проверить тестовой сессией `NV2_`: create → prepare/canon
   с дочитыванием всех чанков → approve → opening → prepare/turn →
   read all chunks → commit → status/history. Проверить что файл
   `open_threads.md` есть в пакете, `relationships.md` изолирован,
   а повтор request_id возвращает исходную сцену без второго хода.
   В конце проверить перезапуск V2 и сохранность тестовой сессии.
8. Проверить, что **старый** адрес Lite по-прежнему возвращает
   `{"engine":"lite"}` на `/healthz`, а тестовый или действующий
   `LITE_` через старый инструмент продолжает отвечать. **Не писать
   тестовые ходы в пользовательские старые сессии**.
9. Лишь после успешной проверки адреса, токена и сессии —
   создать **отдельный плагин ChatNovella V2**. Старый Lite plugin
   не перезаписывать и не менять маршруты `/sessions`.

## API и плагин

Новый V2 работает как **FastAPI REST** с путями
`/v2/instructions`, `/v2/instructions/versions`,
`/v2/novels`, `/v2/novels/{sid}/prepare`,
`/v2/novels/{sid}/chunks/{packet_id}/{index}`,
`/v2/novels/{sid}/turns`, `/v2/novels/{sid}/audit`,
`/v2/novels/{sid}/rollback`, `/v2/novels/{sid}/history`
и т. д. V2 **пока не публикует MCP-инструменты Lite**; для
подключения в ChatGPT Work нужно отдельное новое Actions/OpenAPI
описание с типизированными payload или отдельный V2 MCP-адаптер.
Нельзя просто подменить старый адрес Lite в плагине.

Сессии маршрутизировать по префиксу: `LITE_` → прежний
Lite-плагин и сервер, `NV2_` → новый V2-плагин и сервер.
`CN_` — только архивный старый формат, не обещать автоматическое открытие.

## Обновления после развёртывания

Ветка деплоя специально отделена от `main`, чтобы любой коммит
в основную ветку не переключал V2 или Lite внезапно.
После изменений кода V2 переносить подтверждённые изменения в
деплой-ветку безопасно (сохранять её **собственный root amvera.yaml**),
сначала смотреть CI, затем обновлять только второй проект.

**Критерий готовности:** новый проект Amvera имеет реальный URL,
проверен HTTP и V2, создана тестовая NV2-сессия, а Lite проверен
отдельно. До этого корректный статус — «подготовлено к публикации».
