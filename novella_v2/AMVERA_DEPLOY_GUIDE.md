# ChatNovella V2 — замена Lite в основном проекте Amvera

## Актуальный вариант пользователя: один проект, main → V2

В GitHub `ioshi9212-dotcom/ChatNovella` ветка `main` должна
содержать корневой `amvera.yaml`, запускающий **исключительно**
`novella_v2.amvera_entry:app`.
Остальные старые папки не удалять, но в сервере не импортировать.

- Python 3.12, pip.
- `build.requirementsPath: novella_v2/requirements.txt`
- `run.command: uvicorn novella_v2.amvera_entry:app --host 0.0.0.0 --port 8080 --workers 1`
- `run.containerPort: 8080`, `run.persistenceMount: /data`.
- Данные новых сессий `NV2_`: `/data/chatnovella-v2`.
- Данные прежних `LITE_`: `/data/chatnovella-lite`.
  **Нельзя удалять/очищать /data, менять persistenceMount или переносить
  старые сессии без отдельного разрешения.**
- Токен не нужен и не проверяется ни REST, ни MCP.
- Для MCP, если требуется, задать `CHATNOVELLA_V2_PUBLIC_HOST`
  именем прежнего домена проекта Amvera (без схемы и пути).

## Проверить на прежнем адресе Amvera

1. Обновить **существующее** приложение из `main`, дождаться
   сборки и успешного запуска; отдельный проект не создавать.
2. `GET /healthz` должен вернуть `engine: chatnovella-v2`.
   Если ещё `lite`, переключение не произошло.
3. `GET /v2/instructions` и `GET /openapi.json` без
   заголовков авторизации → HTTP 200. `/mcp` отвечает
   на initialize/tools/list и показывает V2 инструменты.
4. В новой тестовой `NV2_` пройти полный цикл создания,
   утверждения канона, чтения контекста, сохранения сцены,
   отношений, арок и идемпотентности.
5. Проверить сохранность после перезапуска и наличие старых
   данных по пути `/data/chatnovella-lite`, **не открывая
   и не изменяя игровые старые сессии**.

## Откат, если V2 не стартует

Прежний корневой `amvera.yaml` запускает:
`uvicorn chatnovella_lite.server:app --host 0.0.0.0 --port 8080 --workers 1`.
Проверенный предыдущий коммит до переключения:
`d31e3a3e3382b2b321f37d9dd18e0d7aa76501ec`
(позднее в main были только изменения токена V2).
Вернуть прежнюю команду запуска и pip-зависимости старого Lite,
не затрагивая постоянное хранилище. Это возвращает доступ к
`LITE_` через старые инструменты, если их подключение сохранилось.

## Старые чаты

В V2 нет автоматической совместимости с `LITE_` или `CN_`.
Старые данные на диске не пропадают при переключении, но играть
в них через V2 нельзя. Для продолжения потребуется временно
включить прежний Lite или отдельная миграция, которая здесь
**не выполняется**.

## Подключение плагина

MCP endpoint того же основного домена — `/mcp`.
Пакет нового плагина может быть собран так:
`python -m novella_v2.build_plugin --url https://<живой-домен> --output <файл.zip>`.
Режим auth: **none**. Прежние Lite инструменты несовместимы с V2.
Дальнейшие действия перечислены в `novella_v2/WORK_PLUGIN_HANDOFF.md`.

**Предупреждение:** публичный сервер без авторизации позволяет
любому обладателю известного ID сессии читать/менять игру;
создавать новые сессии можно даже без ID. Для приватности
нужны внешние ограничения доступа на стороне хостинга.
