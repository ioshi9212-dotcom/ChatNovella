# ChatNovella V2 — экспериментальная сюжетная память (ветка)

## Зачем

Старый `open_threads.md` — индекс арок с одним коротким `note`. При
продвижении одной части линии этот `note` заменяется, а другие нерешённые
вопросы перестают быть видимыми в текущем рабочем представлении.

Новый `hooks.md` **дополняет**, а не уничтожает или переписывает прежний
индекс. У каждого неразрешённого вопроса, обещания, загадки, цели NPC,
жанровой линии или появления есть самостоятельный стабильный ID и связь
с `arc_id`. Все доказательства исходят из оригинала автора или
конкретной сохранённой сцены.

## Реальный порядок игрового хода

1. **До выбора участников** вызвать `get_v2_director_brief(session_id)`.
   Он возвращает все арки, все живые крючки, всех основных NPC и явные
   авторские сроки. Также извлекает **дословные кандидаты сроков** из
   `original.txt` для старых сессий, где `hooks.md` ещё пуст.
   Источники без авторских сроков не получают выдуманных чисел.
2. Режиссёр учитывает доступную сцену, читательский ввод, NPC-цели,
   нерешённые последствия и авторские условия **без обязательной
   механической ротации** или внезапных событий «для галочки».
3. Выбрать реально необходимых участников, вызвать `prepare_v2_context`,
   загрузить полные карточки участников и дочитать ВСЕ чанки.
   `hooks.md` и `open_threads.md` присутствуют в игровом пакете.
4. Написать сцену по актуальному Skin Builder. Закадровое развитие
   допустимо, но не становится автоматическим знанием POV/NPC.
5. При `save_v2_turn` передать `hook_updates` (по необходимости) с
   точными цитатами окончательного текста. Если реального развития
   нет — `hook_updates=[]`. Закрытие одной загадки не удаляет другие.
6. На 15-м/60-м аудите при непустом `hooks.md` передать
   `report.story` с ключами `hook:<id>` и `arc:<id>` для ВСЕХ
   живых крючков и арок; подтверждать источник, невыполненные
   авторские обязательства и реальные последствия.

## Миграция старых NV2_ сессий

Никакой автоматической реконструкции чужих 150+ ходов «по ощущениям».
Сначала изучить `original.txt` и настоящую историю через
`prepare(kind=canon)` + `search_v2_history`; выбрать отдельные
неразрешённые крючки, каждый с **дословным** источником.

Вызвать `backfill_v2_hooks(session_id, expected_version, additions)`:

- `origin_turn=0`: `source` встречается дословно в оригинале автора;
- `origin_turn=N`: `source` встречается в действующей сохранённой сцене N;
- числовые `window_start/window_end` возможны **только с авторским
  источником** (`origin_turn=0`) и соответствующими цифрами в цитате;
- не использовать последний ещё откатываемый ход как источник бэкфилла;
- не подменять текущие данные и не импортировать закрытые крючки.

Импорт не меняет оригинал, карточки, сцены, отношения, state, timeline
или старый `open_threads.md`. Запись об импорте с источниками остаётся
в `system/audit.jsonl`. После импорта версия увеличивается:
**обязательно сделать новый prepare**, старый packet_id уже недействителен.

## Поля отдельного крючка

`id`, `arc_id`, `title`, `kind` (mystery, commitment, appearance,
consequence, npc_goal, genre), `status` (open, active, blocked),
`detail`, `participants`, `origin`, `origin_turn`,
`last_evidence`, `last_turn`, `window_start`, `window_end`,
`trigger`.

Старый `open_threads.md` оставлен без изменения формата ради совместимости.
Новые сессии могут указать `initial_hooks` при создании только при
наличии настоящих авторских источников. Старые сессии без файла
`hooks.md` читаются с пустым списком; насильственной миграции нет.

## Что **не** делает система

- Не запускает отдельную автономную симуляцию в фоне между ходами.
- Не придумывает поступки NPC, встречи, разгадки и последствия.
- Не объявляет каждый длинный перерыв ошибкой или обязательным событием.
- Не заставляет персонажей появляться по квоте, но обнаруживает и
  показывает пропущенные **явные авторские** окна появлений.
- Не заменяет художественные правила `skin_builder.md`.
- Не гарантирует качество литературной режиссуры сам по себе:
  правильные сведения должны быть применены при следующей сцене.

## Тестирование и развёртывание

Изменения в экспериментальной ветке; **не развёрнуты** на Amvera и не
касаются текущих пользовательских игровых сессий. Для использования
необходимо отдельно обновить существующий MCP-плагин и сервер.
Перед объединением проверить CI для Python 3.11, 3.12, 3.13 и
синтетический тест полной миграции/отката.
