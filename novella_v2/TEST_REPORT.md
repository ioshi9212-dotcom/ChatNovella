# Отчёт о проверках ChatNovella V2

Дата: 23 ноября 2026 года. Проверяется **только** novella_v2/.
Действующие Lite-сессии и Amvera в тестах не использовались.

## Результат

**84 автоматических теста пройдены** на каждой из трёх версий Python:
**3.11, 3.12, 3.13**. Итого 252 успешные проверки.
Проверка GitHub Actions:
https://github.com/ioshi9212-dotcom/ChatNovella/actions/runs/45176204596

## Что фактически проверили

1. **Дословное создание**: русские тексты, эмодзи, CRLF,
   точные границы блоков, уникальные якоря, невозможность потери
   или перекрытия исходных символов; чтение всей анкеты **до утверждения**.
2. **Контекст**: выборочная загрузка карточек и знаний только
   участников сцены; отсутствие чужих карточек; заново подгружаемый
   Skin Builder; безопасное повторное использование того же пакета для
   неизменившегося ввода и чтение только оставшихся чанков.
3. **Чанки 36 000 Unicode-символов**: большие русскоязычные данные,
   контроль SHA-256 полного контекста и каждого чанка, запрет
   сохранения при неполученном чанке или неверной квитанции, обнаружение
   подменённого содержимого. Прямое чтение ровно одного чанка по
   байтовому диапазону, без повторного чтения всего пакета.
4. **Сохранение**: дословные ввод игрока и полный текст сцены,
   отношения, физическое состояние, точечные знания,
   короткие мировые события; пустые изменения не создают мусор.
   Повтор запроса не создаёт второй ход; после перезапуска движка
   повторная запись возвращает исходную сцену. Повторный prepare с
   уже сохранённым request_id возвращает прежнюю сцену без генерации
   и корректно работает даже при обязательном аудите.
5. **Знания**: индивидуальные владельцы, отсутствие автоматической
   передачи сведений другим NPC и в мировую хронологию,
   проверка точной цитаты-источника, запрет новых знаний
   отсутствующему персонажу, отказ от дубликатов фактов.
6. **Хронология**: отсутствие обязательного события в каждом ходе,
   краткие записи, участники, запрет дублей и многострочных подмен.
7. **Состояние и отношения**: только допустимые физические поля,
   проверки состава сцены, монотонности игрового времени и
   запрет тайного изменения отношений персонажа, чья карточка
   не загружена.
8. **Откат**: возврат всех связанных файлов, отсутствие
   отменённого хода в действующей истории при сохранении
   полной архивной записи и метки отката.
9. **Аудиты**: обязательная проверка на ходах 15/30/45/60,
   расширенная на 60-м; обнаружение стёртых ранее записанных
   фактов и событий по полному архиву; запрет аудиту удалять
   предыдущие строки знаний и хронологии; сохранение истории
   исправлений «до/после».
10. **Сбой записи**: восстановление «pending» после имитации
    прерывания между изменением нескольких файлов, частичного
    добавления в архив и отклонение повреждённого хвоста.
11. **120 последовательных игровых ходов**: смена состава NPC,
    добавление Маркуса, накопление персональных знаний,
    развитие отношений, вехи, восемь аудитов,
    откат и повтор хода 91; итог: ровно 120 действующих сцен,
    все факты и состояние согласованы.
12. **Конкурентность**: восемь одновременных попыток
    сохранить один и тот же подготовленный ход;
    проходит только одна, остальные получают ошибку версии.
13. **HTTP API**: полный маршрут создания, предварительного
    чтения, утверждения, старта, сохранения, поиска и отката.
    Bearer-токен обязателен, отсутствие токена закрывает доступ.
14. **Сохранение без раздувания служебных файлов**:
    полный текст сцены хранится в history.jsonl, а не повторяется
    в meta.json на каждом ходе. Архивные записи ДОБАВЛЯЮТСЯ с
    восстановлением после сбоя, а последние три сцены извлекаются
    с конца архива без полного перечитывания.
15. **Защита от циклов**: повторный prepare возвращает прежний packet_id
    и номер следующего чанка; новый запрос без смены данных не начинает
    подготовку заново. Новое request_id не блокируется из-за одинакового
    текста игрока. Технические повторы ограничены в Rules.
16. **Повторение сцен**: короткие естественные диалоги не блокируются,
    длинная почти идентичная сцена сохраняется с предупреждением,
    без искусственного изменения сюжета.
17. **Быстрая целостность**: обнаружение внешнего изменения анкеты,
    карточки, знаний и физического состояния; проверка источников,
    изменившихся после подготовки пакета.
18. **HTTP-тесты новых защит**: повтор prepare с тем же request_id,
    восстановление чтения без потери индексов и возврат уже сохранённой
    сцены вместо создания второй.

## Важные границы результата

- Это детерминированная проверка **движка**, не литературного
  качества генерации. Нет реальной длинной игры с ChatGPT и Amvera V2.
- Сервер может проверить, что источник записанного знания буквально
  присутствует в сохранённой сцене, но не может гарантировать, что
  персонаж действительно понял факт или что событие действительно важно.
  Это надо проверять на настоящих сценах при приёмке.
- Тест восстановления моделирует прерывание записи с корректным
  pending-журналом; физический отказ диска и настоящая потеря питания
  тестами не доказаны.
- Никакого автоматического переноса старых Lite-сессий нет.

## Запуск

Из корня репозитория:

    python -m unittest discover -s novella_v2/tests -v

Для HTTP-тестов установить зависимости:

    pip install -r novella_v2/requirements.txt httpx

Автоматически при изменениях новой папки на main срабатывает
.github/workflows/novella-v2.yml; проверяются Python 3.11, 3.12 и 3.13.
