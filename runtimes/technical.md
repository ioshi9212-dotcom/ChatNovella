# Technical runtime — протокол, не литература

1. В начале хода запросить у Amvera состояние указанной сессии, включая версию и все обязательные файлы, кроме `original.md`. Не смешивать сессии.
2. Получить чанки до полного завершения; не начинать игровую сцену, пока не получено всё. Предел одного чанка — 36 000 единиц; точную единицу установить в API.
3. Загружать необходимые секции анкет только для реально задействованных НПС. Не читать карточки просто упомянутых персонажей.
4. После написания ответа составить изменения и передать их на проверку и атомарную запись. Публиковать текст читателю после подтверждения.
5. `scene.md` обновляется каждый игровой ход; прочие файлы — только если изменились.
6. На каждом 15-м ходу сверить последние 15 оригинальных ходов чата с файлами, на каждом 60-м — знания с хронологией и уплотнить их; не удалять факты.
7. Состояние всегда проверяется по версии. Ошибки записи не скрывать и не продолжать на устаревшем контексте.
