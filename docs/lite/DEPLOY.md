# Изолированный запуск Lite

## Локально

Python 3.12+, Linux (используется `flock` каталогов). Из корня ветки:

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests_lite -v
CHATNOVELLA_LITE_DATA_DIR=./.lite-data uvicorn chatnovella_lite.server:app --host 127.0.0.1 --port 8081 --workers 1
```

Сервис не читает `CHATNOVELLA_DATA_DIR` и не принимает CN_ сессии. Для небольшого
однопроцессного теста используется файловое хранилище; без новой СУБД.

## Отдельное приложение Amvera — ещё НЕ создано

Создать НОВОЕ тестовое приложение, подключить репозиторий ChatNovella, ветку
`feature/chatnovella-lite`. Ветка содержит свой amvera.yaml с командой
`uvicorn chatnovella_lite.server:app --host 0.0.0.0 --port 8080 --workers 1`.
Нельзя менять ветку существующего production-приложения.

Переменные нового приложения:

```text
CHATNOVELLA_LITE_DATA_DIR=/data/chatnovella-lite-test
CHATNOVELLA_LITE_PUBLIC_HOST=<новый-тестовый-домен-без-схемы>
CHATNOVELLA_LITE_PUBLIC_URL=https://<новый-тестовый-домен>
CHATNOVELLA_LITE_API_TOKEN=<новый-случайный-секрет-минимум-24-символа>
```

Отдельный persistent volume `/data`, без монтирования production-данных.
TLS завершает платформа. Публичный сервер требует заданного токена; для
локальной разработки без токена допускается доступ только в изолированной сети.

## ChatGPT: два интерфейса одной реализации

Предпочтительный пользовательский сценарий — отдельное тестовое MCP-подключение
к `https://<новый-тестовый-домен>/mcp` и поддерживаемая клиентом аутентификация
Bearer. Инструкция передаётся сервером; если клиент использует отдельную
инструкцию плагина, скопировать `docs/lite/INSTRUCTIONS.md`. Действующий плагин
ChatNovella Amvera не обновлять. URL нового сервера пока отсутствует, поэтому
готового установленного тестового подключения нет.

Для проверки через Actions импортировать
`https://<новый-тестовый-домен>/openapi.json`; схема генерируется из тех же
типизированных функций, включая canonical server URL и BearerAuth. Указать
токен в настройках API key/Bearer. Этот способ доступен для технического
сравнения; создание Custom GPT не является обязательной частью Lite.

Сначала проверить initialize и tools/list для MCP, healthz и OpenAPI для REST.
Затем создать только новую LITE_ сессию из `example-session.json`, прочитать
полный canon-контекст, получить одобрение, запустить первую сцену отдельной
командой. Для сохранения нужны все чанки и их хеши.

## Ручная игровая приёмка

Нужно пройти минимум 60 художественных ходов через реальный клиент ChatGPT:
проверить инициативу NPC/POV, формат, изменения отношений по событиям, SMS и
телефон, отсутствие передачи мыслей/чужой переписки, появление нового участника,
непрерывность одежды/вещей, события хронологии, контроль 15/30/45/60, повтор
запроса при потерянном ответе, перезапуск тестового сервера и откат последнего
хода. Все записи только в новой тестовой сессии.

Локальные автотесты не заменяют этот прогон. Развёртывание и подключение требуют
отдельного разрешения по ТЗ; текущая ветка подготовлена без их выполнения.
