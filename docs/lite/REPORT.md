# ChatNovella Lite — технический отчёт

Статус: **реализованная локально проверенная тестовая версия**, но полная
игровая приёмка по ТЗ ещё не завершена. Основной сервер не развёртывался,
production-плагин и существующие CN_ сессии не изменялись. Слияние не выполнялось.

Ветка: https://github.com/ioshi9212-dotcom/ChatNovella/tree/feature/chatnovella-lite
База: `e8571b42ac7392d020f14b0d12681719e474a908`.

## Что реализовано

- Новая сессия LITE_, неизменяемый дословный original, полный предложенный canon,
  исправления до утверждения, явное утверждение по хешу. Полная предыдущая
  версия сохраняется при согласованной авторской поправке. Стабильные IDs,
  согласованное добавление нового постоянного NPC без переназначения старых.
- Единый relationships.md: индивидуальные числовые NPC→POV, качественные
  направленные NPC→NPC, частичные изменения с причиной, дельты ±3 либо
  значимое событие, нулевые изменения, новые шкалы и удаление нулевых.
- Персональная приобретённая память по ID: владельцы и источники, дописывание
  предположений/ошибок/опровержений с сохранением ранних записей. Канон не
  размножается по карточкам. Загрузка только выбранных владельцев.
- state.md обновляется каждым ходом; незатронутые сведения сохраняются.
  timeline.md изначально пуст, значимые события добавляются без переписывания.
- Полный novel.md, два engine-файла, отношения/состояние/хронология и три
  полные сцены каждый ход; Unicode-чанки с SHA256 и квитанцией полного чтения.
- Единая запись финальной сцены и всех изменений, версии, идемпотентность,
  восстановление pending-транзакции, откат последнего хода без потери архива.
- Аудиты 15/30/45/60 блокируют следующий ход. Полные 15 сцен; на 60-м вся
  хронология и память всех NPC, включая отсутствующих. Подтверждённые исправления
  не меняют канон/историю и не стирают прежнюю память/хронологию.
- MCP `/mcp`, REST для Actions, генерируемая OpenAPI, Bearer, health endpoint,
  отдельная конфигурация запуска. 12 MCP-инструментов; plan/review не нужны.

## Что действительно запущено

```text
python -m unittest discover -s tests_lite -q
Ran 25 tests — OK

python scripts/lite_smoke.py
TCP HTTP smoke PASS
12 OpenAPI paths / 12 MCP tools
saved_exact_scene=true / idempotent=true / rollback=true

python -m compileall -q chatnovella_lite tests_lite
PASS

git diff --check
PASS
```

В 25 тестах есть 60 ПОСЛЕДОВАТЕЛЬНЫХ серверных ходов одной сессии с завершением
аудитов 15/30/45/60. Это детерминированная проверка хранения, не реальная игра
GPT. Проверены: анкета 94 600 Unicode-символов, кириллица/emoji/CRLF, все чанки,
сохранность original, блокировка канона, направления отношений, источники
знаний, ошибочное убеждение и опровержение, входящий NPC, оффскрин-события,
одежда/предметы, незначимое событие без записи в хронологию, ошибка диска,
имитация прерывания, повтор request_id, конкурентные записи, откат всех
затронутых данных, восстановление после пересоздания Store, изоляция сессий,
полное чтение аудита, запрет изменения канона аудитом и восстановление памяти
отсутствующего NPC на 60-м ходу.

TCP smoke действительно запускает uvicorn отдельным процессом и проходит
HTTP-протокол на localhost с Bearer, полной загрузкой контекста, сохранением
тестового художественного отрывка, повтором, откатом и MCP tools/list. Это
самостоятельно подготовленный тестовый отрывок, не чужая игровая сцена и не
60-ходовое поведение ChatGPT. Старый production API при этих тестах не вызывается.

## Что ещё не проверено и чего версия не обещает

- **Реальные художественные сцены пользовательской новеллы и минимум 60 ходов
  через ChatGPT Actions/MCP ещё не пройдены.** Поэтому нельзя объявлять
  выполненными все критерии пользовательской приёмки.
- Нужен отдельный разрешённый запуск тестового приложения и новое подключение
  ChatGPT. Готовая инструкция и example-session.json находятся рядом; URL нового
  приложения пока отсутствует. Текущий плагин автоматически не переключается.
- Сервер не доказывает литературную верность, естественность NPC, полноту
  понимания анкеты и логическую достаточность источника знания. GPT обязан
  применять эти правила. Наличие цитаты/причины не является доказательством.
- Сбой записи и прерывание протестированы инъекцией ошибок; физическое отключение
  диска, power-loss, восстановление из внешней резервной копии не проверялись.
- Простая файловая реализация переписывает history.jsonl при транзакции;
  масштабируемость на многолетние гигантские истории не измерена. Linux/POSIX,
  один экземпляр сервиса, локальный persistent volume. Нет NFS/distributed режима.
- Нет миграции старых CN_ сессий, пользовательских аккаунтов/ACL или отдельного
  потокового загрузчика исходника. Исходник собирается из частей до create.
  Технический реестр нового NPC расширяется только с явной поправкой канона.

Следующий шаг после отдельного разрешения — изолированное развёртывание по
DEPLOY.md и реальный игровой прогон, а не автоматическое слияние в main.
