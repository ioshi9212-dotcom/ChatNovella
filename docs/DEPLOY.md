# Запуск ChatNovella на Amvera — MVP

## Что реализовано
MCP-сервер с HTTP-транспортом, постоянным хранением в `/data`, отдельными
сессиями, исходником 1:1, выборочной загрузкой NPC, полными чанками
по 36 **тысяч Unicode-символов**, версионными сохранениями и обязательным
аудитом на 15-м/60-м ходе. Файлы новелл — обычный Markdown.
Сервер НЕ сочиняет сцен и НЕ проверяет смысл скрытых знаний автоматически.

## Развёртывание на Amvera
1. Создать **новый отдельный** проект (не существующий RomanAI).
2. Подключить GitHub `ioshi9212-dotcom/ChatNovella`, ветка `main`.
3. Среда Python/pip. В корне уже есть `amvera.yaml`:
   Python 3.12, порт 8080, `/data`, один процесс uvicorn.
4. Переменные окружения **не обязательны**. Без `CHATNOVELLA_API_TOKEN` сервер
   запускается и принимает запросы без Bearer-токена.
5. Запустить сборку. Проверка: `GET https://<ваш-домен>/health` →
   `{"status":"ok"}`. MCP endpoint: `/mcp` (проверить после деплоя).

### Публичный домен и ошибка инициализации MCP

По умолчанию разрешён домен `chatnovella-yumikofv.waw0.amvera.tech`.
Для другого домена задайте `CHATNOVELLA_PUBLIC_HOST` — только имя хоста,
без `https://`, пути и порта. FastMCP проверяет заголовки Host и Origin;
публичный домен и `https://chatgpt.com` разрешены явно. Защита от DNS rebinding
остаётся включённой. Порт uvicorn сам по себе не настраивает этот список.

Если `/health` отвечает, а `/mcp` возвращает `421 Invalid Host header`,
проверьте домен в списке разрешённых и пересоберите приложение из свежего
коммита. Затем проверьте POST `initialize`, `tools/list` и чтение через
`list_novella_sessions`. Один успешный `/health` не доказывает работу MCP.

При `initialize` сервер передаёт стартовую инструкцию из
`docs/PLUGIN_INSTRUCTIONS.md`: порядок настройки, чтение всех чанков,
сохранение до публикации и аудиты. Подключение — обычный MCP-плагин
ChatNovella; отдельный Custom GPT не требуется.

**Внимание:** отсутствие токена не ограничивает доступ владельцем панели Amvera.
Если у приложения есть публичный URL, любые лица, имеющие доступ к этому URL,
могут обращаться к MCP и читать или изменять сессии. Для закрытого доступа
можно позднее задать `CHATNOVELLA_API_TOKEN` — случайный секрет минимум
24 символа — тогда MCP потребует `Authorization: Bearer <секрет>`.
Конкретный способ передачи авторизации из ChatGPT ещё не проверен.

## Локальная проверка
```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
export CHATNOVELLA_DATA_DIR="./local_data"
uvicorn chatnovella.mcp_server:app --port 8080
```

На Amvera данные находятся под `/data/chatnovella/sessions/CN_.../`:
- `original.md` — неизменяемый текст читателя.
- `current.json` — атомарный указатель на версию, ход, статус, аудиты.
- `revisions/v00000000/` и следующие — полные читаемые состояния.
- `revisions/v.../system/turns.jsonl` — точные сообщения читателя и GPT.
- `/data/chatnovella/packets/` — подготовленные чанки.

Обновление указателя выполняется атомарно после записи полного состояния.
Не редактировать текущую версию вручную при работающем сервере.

## MCP: порядок действий
**Новая новелла:** после «Подтверждаю» вызывается
`create_novella_session` (дословный оригинал + рабочие novel и POV),
затем `save_setup_files` с подготовленными карточками и состояниями.
После заполнения GPT вызывает `get_setup_report`. Если остаются пропуски, спрашивает читателя: написать самой, разрешить дополнить или пропустить. Затем `finish_setup`; параметр `reader_approved_gaps=true` допускается только после явного решения читателя.
Первую сцену создавать только после команды пользователя.

**Продолжение в другом чате:** `get_session_status` по ID,
`prepare_novella_turn` со списком действительно участвующих НПС,
`read_novella_chunk` для **всех** индексов от 0 до count-1.
После написания сцены передать полный текст и изменённые файлы через
`save_novella_turn`; публикация ответа только после успешного сохранения.

Пример участников:
```json
[
  {"id": "NPC_001", "mode": "physical"},
  {"id": "NPC_002", "mode": "phone"},
  {"id": "NPC_003", "mode": "observer", "need_past": false},
  {"id": "NPC_004", "mode": "mentioned"}
]
```

Режимы `message` и `mentioned` не загружают анкету.
При `phone` нет внешности, при `observer` нужны способности, характер,
личные знания и отношения. Полное прошлое — только если `need_past=true`.

**Аудиты:** если версия имеет `audit_15_due` или `audit_60_due`,
следующий игровой ход временно заблокирован. GPT вызывает
`prepare_novella_audit`, получает все чанки, сверяет и сохраняет результат
через `finish_novella_audit`. При ходе 60 проводятся оба аудита
(сначала 15, затем 60) по текущей версии состояния.

## Границы MVP
- Правила непрерывности тела, одежды и предметов описаны, но проверка
  их **смысла** пока остаётся за GPT. То же касается утечек знаний.
- Сервер уже проверяет ID путей, дубли предметов, числовые диапазоны
  отношений и устаревшие версии сессий.
- Очистка старых пакетов и политика архивирования ещё не сделаны.
- Лимит 36 000 — **символы**, а не токены. Все части файла передаются;
  общий размер контекста самой модели этим не увеличивается.
- Текущая конфигурация рассчитана на один процесс uvicorn.
- Живой деплой на Amvera и интеграция с ChatGPT ещё не выполнены.

## Загрузка общих правил и оформления в каждом игровом ходе

`prepare_novella_turn` загружает с файловой системы развёрнутого приложения
в таком порядке:
1. `rules/technical.md` — общие технические Rules;
2. `runtimes/director.md`, `npc.md`, `pov.md`, `knowledge.md`,
   `relations.md`, `arcs.md`, `continuity.md`, `boundaries.md`;
3. `skin/skin_builder.md` — только визуальное оформление;
4. заполненные файлы конкретной сессии;
5. нужные модули анкет присутствующих или участвующих НПС.

Правила и оформление автоматически включаются **при каждом** вызове
`prepare_novella_turn`, а не только при первом запуске сессии.
Файлы не создаются в `/data`: там живёт только состояние новеллы.
В ответе инструмента возвращается список `engine_files`; полный текст
каждого файла находится в чанках `read_novella_chunk`, без обрезания.
Если общий файл отсутствует, пакет не выдаётся, чтобы GPT не начал сцену
без нужных инструкций. Для обновления правил нужна новая сборка Amvera
из ветки `main`.
